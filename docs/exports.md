# Offline KGX and SSSOM Exports

`python -m dufmech.exports` validates the native corpus and reports pending export
changes. `--apply` writes the three artifacts below; `--check` validates inputs
and compares every generated byte without writing. `--root PATH` selects another
checkout. Exit codes are 0 for success, 1 for invalid inputs, stale exports or I/O
failure, and 2 for invalid CLI arguments. All modes are offline.

| `exports/kgx/nodes.tsv` | Every native Pfam record and the referenced InterPro accessions |
| `exports/kgx/edges.tsv` | One source-backed Pfam-to-InterPro association per recorded integration |
| `exports/sssom/dufmech.sssom.tsv` | The same associations with standard SSSOM columns and prefix metadata |

## Semantics and Provenance

[InterPro integrates member database signatures](https://www.ebi.ac.uk/training/online/courses/interpro-quick-tour/interpro-data/)
representing families, domains or sites. The frozen worklist retains the
integrated accession but not the InterPro label, entry type, per-association
matching procedure or confidence. Accordingly:

- KGX uses `biolink:NamedThing` for both endpoints, because the native schema does
  not distinguish protein families, domains and other signature types. It uses
  [`biolink:related_to`](https://biolink.github.io/biolink-model/related_to/).
- SSSOM uses the associative
  [`skos:relatedMatch`](https://www.w3.org/TR/skos-reference/skos.html#relatedMatch),
  never `exactMatch`, equivalence, or a functional predicate.
- `semapv:UnspecifiedMatching` follows the
  [SSSOM fallback guidance](https://mapping-commons.github.io/sssom/1.0/matching-tool-implementation-guide/)
  when the per-mapping method is unavailable. This export does not represent a
  new manual mapping review. `object_label` and `confidence` are deliberately empty.
- Pfam labels and descriptions come from validated native records. Descriptions,
  seed classifications and automated characterization statuses are attributes,
  not scientific assertions. InterPro nodes have no borrowed Pfam labels or
  curation statuses. Curated assertions, causal graphs, discussions, datasets and
  cross-corpus links are validated but are outside this export's scope. Causal
  edges are not exported as Pfam-to-InterPro identity associations.

KGX records the provider URL, upstream URL, snapshot ID, repository-relative
snapshot path, exact JSON SHA-256 and snapshot timestamp. Edges also name the
native record and source field. SSSOM carries the upstream record in
[`mapping_provider`](https://mapping-commons.github.io/sssom/mapping_provider/),
source namespaces in `subject_source`/`object_source`, and the
same snapshot, record and field details in `comment`. These are standard SSSOM
slots; no profile extensions are needed. `mapping_tool` identifies the native
export module. Snapshot timestamps are retained as
provenance, never presented as new acquisition or review dates. In particular,
the October 5 snapshot was an offline reclassification of an earlier freeze;
its checked manifest retains that lineage. Edge IDs hash the triple and source
snapshot digest. They do not depend on the working directory or export time.

## Validation and Serialization

The producer calls `dufmech.records.load_records`: it verifies selected frozen
worklists, manifests, TSV agreement and reclassification lineage; replays optional
verified scores; validates closed-schema overlays, canonical history, review
gates and assertion evidence; and requires stored family projections and their
ownership manifest to match. It never regenerates or writes `data/families`,
curation, history or source snapshots. Malformed or stale native inputs fail
before output publication. Source and output path symlinks are rejected using
the native path guards. Existing exports are read through noncreating,
descriptor-confined directory walks and nonblocking, no-follow file opens;
regular-file checks and byte reads use the same descriptor. A leaf replaced by
a symlink or FIFO cannot redirect or block these reads. Unrelated source
pipelines are not exported.

Rows and nodes have stable identifier ordering. TSV uses UTF-8, LF and no CSV
quoting. In text cells, backslashes become `\\`, double quotes become `\u0022`,
and tab/newline/carriage return become `\t`, `\n`, `\r`. Other control and Unicode
line separators use `\uXXXX`. This is reversible display escaping, not a label
correction: a consumer requiring the exact source string must decode these
escapes once. CSV and literal tab/newline readers see identical cell strings.
The writer checks this agreement for every rendered table. The SSSOM YAML
preamble has to be removed before passing its table to a generic TSV reader.

All payloads are validated and staged before publication. Each file replacement
is atomic through pinned directory descriptors; existing identical files are
left untouched. The three-file batch is not a filesystem transaction: interruption
between replacements can leave a mixed generation, which `--check` detects and
`--apply` repairs. Callers must serialize writers (fleet callers use the CLAW
repository operation lease); a detected edit during staging aborts publication.
Post-staging comparisons use the same pinned directories as publication, so a
replacement parent cannot hide an edit to the actual destination. If a pinned
directory is renamed, publication remains there and never follows its replacement.
Apply replaces only these three generated export files. Check and dry-run create
no directories or lock files. No export operation rewrites native family YAML.

## Integration Recipes

The native recipe preserves argument boundaries and defaults to a read-only
preview. Full `just qc` invokes the reproducibility check after native record
validation:

```bash
just exports
just exports --check
just exports --apply
```

The installed entry point is `dufmech-exports`; the module CLI remains available.
Validate actual artifacts using the canonical shared contracts:

```python
from pathlib import Path
from kg_microbe_kgx.contract import check_graph
from kg_microbe_sssom.contract import check_file
from kg_microbe_sssom.contract import _slot_names

assert _slot_names(), "sssom-schema must be installed"
assert not check_graph(Path("exports/kgx/nodes.tsv"), Path("exports/kgx/edges.tsv"))
assert not check_file(Path("exports/sssom/dufmech.sssom.tsv"))
```

Run focused native tests with `python -m pytest tests/test_exports.py -q`.
The shared-contract test requires the two canonical packages on `PYTHONPATH`
and an installed `sssom-schema` with a nonempty slot set. Missing packages or
the schema fallback fail the test; no contract test is skipped. These are test
dependencies, not native producer dependencies. The integration owner supplies
the canonical CLAW source and adds `sssom-schema` to the development dependencies.
These contracts check interchange shape and identifiers, not biological truth.
